# public_dataset_a 文档处理结果验证方案

## 1. 方案目的

本方案面向 `public_dataset_a` 中全部原始文档资源，建立一套可直接执行的文档处理结果验证体系，用于系统性评估文档预处理、结构化抽取、元数据生成、合规筛查和后续检索可用性是否达标，并为比赛项目的文档处理链路提供统一验收依据、问题追溯机制和整改闭环标准。

本方案遵循以下原则：

- `以真实数据集为边界`：所有验证范围、抽样数量、工具适配和资源配置均以 `public_dataset_a` 的实际文件结构为准。
- `以可执行为核心`：输出不仅包括书面方案，还包括验证记录表、问题整改台账模板和批量校验脚本骨架。
- `以检索可用为最终目标`：验证不仅看“文本有没有抽出来”，还看是否足以支撑证据召回、定位和问答。

## 2. 数据集范围与对象画像

### 2.1 数据范围

本方案覆盖目录：

- `public_dataset_a/raw`
- `public_dataset_a/questions/group_a`

其中 `questions/group_a` 不直接作为文档处理对象，但作为文档处理结果是否“可服务题目”的验证基准。

### 2.2 数据规模统计

基于工作区实际统计，`public_dataset_a/raw` 共包含 `573` 个原始文件，总体积约 `341.41 MB`，分布如下：

| 领域目录 | 文件数 | 体积(MB) | 主要格式 | 说明 |
|---|---:|---:|---|---|
| `financial_contracts` | 14 | 105.57 | PDF | 金融合同/募集说明类长文档 |
| `financial_reports` | 10 | 104.85 | PDF | 上市公司年度报告 |
| `insurance` | 16 | 7.11 | PDF | 保险产品条款与责任说明 |
| `regulatory` | 513 | 70.52 | HTML / PDF / TXT | 监管网页正文、附件、规范化法规文本 |
| `research` | 20 | 53.36 | PDF | 研报、研究材料 |

### 2.3 文档类型与处理复杂度

按处理复杂度和验证重点，可将数据分为五类：

1. `财务报告类 PDF`
   - 典型风险：表格跨页、目录干扰、页眉页脚噪声、财务指标错列
2. `金融合同类 PDF`
   - 典型风险：条款编号抽取错误、责任条款切分过碎、关键条件跨段
3. `保险条款类 PDF`
   - 典型风险：免责/给付规则误切、数值条件漏抽、同义表述混淆
4. `监管网页 HTML + 附件 PDF`
   - 典型风险：网页导航噪声、正文与附件映射丢失、发布日期/标题抽取错误
5. `监管规范化 TXT`
   - 典型风险：目录重复、章节结构保留不完整、条款边界错位

### 2.4 标注规则与原始校验基线

经工作区核查，`public_dataset_a` 未发现单独的官方“文档处理校验标准说明书”或 README。现阶段可直接采用的原始校验基线来自以下四类信息：

1. `目录与命名规范`
   - 文档按领域分目录存储
   - 文件名与题目 `doc_ids` 具有映射关系，如 `annual_byd_2024_report`、`strict_v3_017_中华人民共和国反洗钱法`
2. `题目标注文件`
   - `questions/group_a` 中共 5 个 JSON 文件，每个 20 题，共 100 题
   - 每题包含字段：`qid`、`domain`、`split`、`question`、`options`、`answer_format`、`type`、`doc_ids`
   - 文档处理结果最终必须能服务于这些 `doc_ids` 指向的证据检索
3. `原始文档内容结构`
   - 监管 TXT 显式包含章节、目录、条款号，可作为条款结构校验基线
   - 监管 HTML 中含 `ArticleTitle`、`PubDate`、`ContentSource` 等元信息，可作为元数据抽取基线
4. `比赛题目形态`
   - 100 题中 `doc_ids` 数量分布为：2 文档题 81 题、3 文档题 7 题、4 文档题 12 题
   - `answer_format` 分布为：`multi` 65 题、`tf` 20 题、`mcq` 15 题
   - 说明文档处理结果必须适配多文档对比、判断题、计算题和逻辑推理题

### 2.5 待验证的文档处理核心环节

本次验证聚焦以下文档处理环节：

1. `格式标准化`
   - 文件可读性、编码统一、格式识别、扩展名与真实类型一致性
2. `内容抽取准确性`
   - 正文抽取、章节保留、条款边界、表格与关键数字保留
3. `元数据完整性`
   - 标题、领域、页码、章节路径、条款号、文档来源、附件映射
4. `内容逻辑一致性`
   - 目录与正文一致、条款顺序连续、表格指标不乱序
5. `合规性筛查`
   - 敏感信息识别、版权来源保留、网页来源与发布日期记录
6. `检索可用性`
   - 文档处理结果能否支撑后续证据召回与题目定位

## 3. 前期准备工作

### 3.1 技术工具清单

| 工具类型 | 推荐工具 | 用途 |
|---|---|---|
| 文件格式检测 | `python-magic` / `mimetypes` | 检测扩展名与真实 MIME 是否一致 |
| PDF 文本抽取 | `PyMuPDF` / `pdfplumber` | 读取正文、页数、表格、段落 |
| OCR | `PaddleOCR` | 扫描件或图片型 PDF 识别 |
| HTML 解析 | `BeautifulSoup4` / `lxml` | 正文清洗、元信息抽取、附件链接校验 |
| 编码检测 | `charset-normalizer` | 判断 TXT/HTML 编码一致性 |
| 批量校验脚本 | Python 3.11 | 输出结构化验证报告 |
| 数据统计 | `pandas` | 汇总质量指标、问题台账 |
| 人工复核 | Excel / CSV 模板 | 抽样记录与问题登记 |


## 4. 核心验证体系

### 4.1 分层指标框架

本方案采用四层指标体系：

1. `基础维度`
2. `内容维度`
3. `合规维度`
4. `效率维度`

### 4.2 基础维度指标

| 指标 | 定义 | 计算规则 | 合格阈值 |
|---|---|---|---|
| 格式合规率 | 文件可被正确识别与打开的比例 | `格式正常文件数 / 总文件数` | `>= 99.5%` |
| 文件完整率 | 文件无损坏、无截断的比例 | `完整文件数 / 总文件数` | `>= 99.0%` |
| 编码统一率 | HTML/TXT 可正常解析为 UTF-8 或可稳定转码的比例 | `编码正常文件数 / HTML+TXT总文件数` | `>= 99.0%` |
| 命名映射成功率 | 文件名与 `doc_ids`/元数据可正确映射的比例 | `映射成功文件数 / 需映射文件数` | `= 100%` |
| 元数据基础完备率 | 标题、领域、来源、页码/章节等基础字段齐全比例 | `字段齐全文档数 / 总文档数` | `>= 98.0%` |

### 4.3 内容维度指标

| 指标 | 定义 | 计算规则 | 合格阈值 |
|---|---|---|---|
| 正文抽取准确率 | 抽样中文本与原文一致的比例 | `正确抽取样本数 / 抽样样本数` | `>= 97.0%` |
| 字段完整率 | 标题、条款号、章节路径、页码、表格标识等字段完整率 | `完整字段数 / 应有字段数` | `>= 95.0%` |
| 条款边界准确率 | 法规/合同/保险条款切分正确率 | `边界正确条款数 / 抽样条款总数` | `>= 96.0%` |
| 数值保真率 | 金额、比例、日期等关键数值抽取准确率 | `正确数值数 / 抽样数值总数` | `>= 98.0%` |
| 表格还原可用率 | 财报/合同表格可用于后续检索和核对的比例 | `可用表格数 / 抽样表格数` | `>= 90.0%` |
| 逻辑一致率 | 目录、章节顺序、条款编号、附件映射逻辑一致比例 | `一致样本数 / 抽样样本数` | `>= 95.0%` |
| 检索支撑率 | 标注题目关联文档中的关键证据可被定位的比例 | `Top-K 可召回题数 / 抽样题数` | `>= 92.0%` |

### 4.4 合规维度指标

| 指标 | 定义 | 计算规则 | 合格阈值 |
|---|---|---|---|
| 敏感信息筛查通过率 | 非预期个人敏感信息未被异常暴露的比例 | `通过文档数 / 总文档数` | `= 100%` |
| 版权来源保留率 | 来源机构、发布日期、标题、原始路径等保留完整比例 | `保留完整文档数 / 应保留文档数` | `>= 99.0%` |
| 外链附件映射准确率 | HTML 与附件 PDF 的关联准确率 | `映射正确数量 / 抽样映射总数` | `>= 98.0%` |
| 合规缺陷关闭率 | 已识别合规问题关闭比例 | `已关闭问题数 / 总问题数` | `= 100%` |

### 4.5 效率维度指标

| 指标 | 定义 | 计算规则 | 合格阈值 |
|---|---|---|---|
| 平均处理耗时 | 单文档平均处理时长 | `总处理时长 / 文档数` | 按类型分阈值 |
| PDF 平均处理耗时 | 普通 PDF 平均处理时间 | `PDF总耗时 / PDF数` | `<= 45 秒/份` |
| HTML 平均处理耗时 | HTML 解析平均处理时间 | `HTML总耗时 / HTML数` | `<= 5 秒/份` |
| TXT 平均处理耗时 | TXT 解析平均处理时间 | `TXT总耗时 / TXT数` | `<= 3 秒/份` |
| 自动化覆盖率 | 可由脚本自动校验的项目占比 | `自动校验项数 / 总校验项数` | `>= 75.0%` |
| 人工复核触发率 | 需要进入人工复核的文档比例 | `人工复核文档数 / 总文档数` | `<= 20.0%`，超出需优化脚本 |

## 5. 落地实施流程

### 5.1 全流程节点

1. `准备阶段`
   - 数据盘点
   - 建立文档清单
   - 确认映射规则与验证口径
2. `自动化初检`
   - 格式、编码、完整性、元数据、结构初检
3. `预验证试点`
   - 对 10% 样本执行小范围验证
   - 校准指标阈值和脚本规则
4. `全量自动化检测`
   - 跑全量文档，形成问题清单
5. `人工抽样复核`
   - 对高风险样本和自动化命中样本进行复核
6. `问题分级整改`
   - 输出问题台账、责任人、期限、修复建议
7. `复查与验收`
   - 对整改项进行复查，形成最终验收结论

### 5.2 抽样校验设计

#### 抽样原则

- 采用 `分层抽样 + 风险加权抽样`
- 必须覆盖所有文档类型、所有格式和所有处理场景
- 对高复杂度类别增加抽样权重，特别是：
  - 监管 HTML + 附件 PDF
  - 财报 PDF
  - 保险/合同中的复杂条款页

#### 预验证试点样本量

按照“总量不低于 10%”和“按格式分层向上取整”的原则，建议试点样本如下：

| 类别 | 总量 | 试点样本量 | 说明 |
|---|---:|---:|---|
| `financial_contracts/pdf` | 14 | 2 | 覆盖条款密集型合同 |
| `financial_reports/pdf` | 10 | 1 | 覆盖财报表格型文档 |
| `insurance/pdf` | 16 | 2 | 覆盖免责/给付条款 |
| `research/pdf` | 20 | 2 | 覆盖长段落研究报告 |
| `regulatory/html` | 377 | 38 | 覆盖网页正文清洗与元数据 |
| `regulatory/attachments/pdf` | 130 | 13 | 覆盖网页附件映射 |
| `regulatory/txt` | 6 | 1 | 覆盖规范化法规文本 |

试点合计 `59` 份文档，占总量 `10.30%`，满足“10% 预验证”要求。

#### 人工抽样复核量建议

- 试点阶段：全部 59 份样本均进行人工复核
- 全量阶段：
  - 自动检测通过文档：抽检 `5%`
  - 自动检测异常文档：抽检 `100%`
  - 财报与监管附件类：额外加抽 `10%`

### 5.3 人工复核设计

#### 触发场景

出现以下任一情况时必须进入人工复核：

- 文件无法解析或正文长度异常
- HTML 抽取结果正文缺失、导航噪声过多
- 财报/合同类文档表格抽取失败
- 条款编号不连续或条款边界错位
- 数值字段抽取缺失或明显异常
- `doc_ids` 与文件名映射失败
- 自动校验脚本命中 `critical/high` 级问题

#### 复核流程

1. 数据工程师导出待复核清单
2. 业务复核人员对照原文逐项核验
3. 合规审核人员检查来源和敏感信息
4. 验证负责人签署复核结论

#### 权责划分

| 环节 | 执行方 | 审核方 |
|---|---|---|
| 自动化初检 | 数据工程师 | 验证负责人 |
| 内容复核 | 业务复核人员 | 验证负责人 |
| 合规复核 | 合规审核人员 | 验证负责人 |
| 整改执行 | 对应模块负责人 | 整改负责人 |
| 复查验收 | 验证负责人 | 项目负责人 |

### 5.4 自动化工具校验设计

批量校验脚本建议支持以下能力：

1. 遍历 `public_dataset_a/raw` 全量文件
2. 输出文件级清单：
   - 文件路径
   - 领域
   - 格式
   - 大小
   - MIME 检测结果
3. 输出内容级清单：
   - 正文长度
   - 页数
   - 条款号数量
   - 表格数量
   - 编码检测结果
4. 输出校验结论：
   - `pass`
   - `warning`
   - `fail`
5. 输出问题分级：
   - `critical`
   - `high`
   - `medium`
   - `low`

自动化脚本最少覆盖以下校验项：

- 扩展名与 MIME 一致性
- 文件能否打开
- PDF 页数 > 0
- HTML 是否存在 `title` / `ArticleTitle` / `PubDate`
- TXT 是否包含可识别章节或条款文本
- 正文长度是否落在合理区间
- 文件名与 `doc_ids` 是否可映射

### 5.5 问题追溯与整改设计

#### 问题分级

| 等级 | 定义 | 处理时限 |
|---|---|---|
| `Critical` | 文档无法处理、正文严重缺失、元数据失真、合规风险 | 24 小时 |
| `High` | 条款/表格/关键数值抽取错误，影响题目证据定位 | 2 个工作日 |
| `Medium` | 章节路径、页码、附件映射等部分不完整 | 3 个工作日 |
| `Low` | 样式噪声、少量格式不规范、不影响检索 | 5 个工作日 |

#### 整改闭环

1. 问题登记进入台账
2. 指定责任人和修复时限
3. 提交整改说明
4. 复查人按原问题点逐项验证
5. 闭环后更新状态为 `已关闭`

#### 复查要求

- `Critical/High` 问题必须 100% 复查
- `Medium/Low` 问题按批次抽检 30%，若不通过则提升为全量复查

## 6. 预验证试点设计

### 6.1 目标

预验证的目标不是直接“判定最终合格”，而是验证三件事：

1. 指标定义是否合理
2. 自动化脚本是否能有效发现问题
3. 人工复核工作量是否在可控范围内

### 6.2 试点执行步骤

1. 按 `59` 份样本建立试点样本清单
2. 跑自动化脚本输出初检结果
3. 对全部 59 份样本做人工复核
4. 统计：
   - 自动发现率
   - 人工补充发现率
   - 各指标通过率
   - 平均耗时
5. 调整：
   - 阈值过严/过松的指标
   - 误报较高的规则
   - 人工复核触发条件
6. 输出最终版方案

### 6.3 试点验收口径

若试点阶段出现以下情况，需要回炉优化方案：

- 自动化误报率 > `15%`
- 自动化漏报率 > `10%`
- 人工复核触发率 > `30%`
- 高风险问题集中出现在某一类文档上
- 关键指标阈值在试点后明显不适配

## 7. 风险预案

| 风险 | 表现 | 预案 |
|---|---|---|
| PDF 复杂版式导致抽取失败 | 表格乱序、正文缺失 | 分类型策略处理，表格页单独校验 |
| HTML 页面噪声过多 | 导航、页脚、脚本混入正文 | 定制正文选择器与黑名单规则 |
| 监管 HTML 与附件映射丢失 | 证据来源不完整 | 建立 `html_id -> attachment_id` 映射表 |
| 财报页数过多影响试点效率 | 人工复核压力过大 | 重点页抽样，结合表格页优先核验 |
| 合规标准不明确 | 敏感信息边界模糊 | 由合规审核人员给出白名单/黑名单规则 |
| 阈值过严或过松 | 验证结果失真 | 通过 10% 预验证校准阈值 |

## 8. 交付成果

本方案落地后应形成以下交付物：

1. 本书面验证方案
2. 试点样本清单
3. 自动化初检报告
4. 人工复核记录表
5. 问题整改台账
6. 试点复盘报告
7. 最终验收报告

## 9. 执行结论

基于 `public_dataset_a` 的真实结构，文档处理结果验证必须采用“`自动化初检 + 分层抽样 + 人工复核 + 台账整改 + 复查闭环`”的组合方式，尤其要重点关注：

- `regulatory` 类数据中 HTML、附件 PDF、规范化 TXT 的异构混合场景
- 财报类 PDF 的表格完整性与数值保真
- 合同与保险条款类文档的条款边界准确性
- 文档处理结果对题目 `doc_ids` 和后续证据召回的实际支撑能力

只有当基础、内容、合规、效率四层指标同时满足阈值，并通过 10% 预验证试点校准后，文档处理链路才可进入正式比赛使用阶段。
