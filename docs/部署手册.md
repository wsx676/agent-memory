# 部署手册

## 1. 环境要求

| 组件 | 版本 | 说明 |

| Node.js | 20+ | 前端构建 |
| npm | 10+ | 前端包管理 |
| Python | 3.11+ | 后端运行时 |
| pip | 23+ | Python 包管理 |

## 2. 环境变量配置

在项目根目录创建 `.env` 文件：

```env
# Qwen LLM 配置（必须）
ENABLE_QWEN_LLM=1
DASHSCOPE_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
MODEL_NAME=qwen3.7-plus-2026-05-26

# 可选：自定义 API 端点（默认为 DashScope）
# DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

| 变量 | 必填 | 说明 |
|------|------|------|
| `ENABLE_QWEN_LLM` | 是 | 设为 `1` 启用 Qwen LLM |
| `DASHSCOPE_API_KEY` | 是 | DashScope API Key |
| `MODEL_NAME` | 是 | Qwen 模型名称 |
| `DASHSCOPE_BASE_URL` | 否 | API 基地址，默认为 DashScope |

> **安全提示**：`.env` 文件已加入 `.gitignore`，切勿提交到版本控制。

## 3. 前端部署

## 4. 后端部署

```bash

python -m pip install -r requirements.txt

# 启动后端服务
python -m uvicorn api.main:app --host 0.0.0.0 --port 8000
```

## 6. 评测流水线

### 6.1 运行评测

```bash
# 全量评测（100 题）
python scripts/eval_group_a_qwen.py --suffix _full

# 抽样评测（20 题，从第 0 题开始）
python scripts/eval_group_a_qwen.py --suffix _sample --offset 0 --limit 20

# 指定 chunks 文件（默认 chunks_merged.jsonl）
python scripts/eval_group_a_qwen.py --suffix _full --chunks-file chunks.jsonl
```

### 6.2 命令行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--offset` | 0 | 起始题号偏移 |
| `--limit` | 0 | 题目数量（0=全部） |
| `--suffix` | 空 | 输出文件后缀 |
| `--chunks-file` | chunks_merged.jsonl | 使用的切片文件 |

### 6.3 评测产出

输出目录：`validation_outputs/public_dataset_a/testing/group_a_qwen_eval/`

| 文件 | 说明 |
|------|------|
| `answer.csv` | **赛题提交文件**（qid, answer, prompt_tokens, completion_tokens, total_tokens） |
| `results__<suffix>.jsonl` | 逐题详细结果（含 fallback、自检状态、检索质量等） |
| `summary__<suffix>.json` | 汇总统计（Token 用量、耗时、分 domain 统计） |
| `summary__<suffix>.md` | Markdown 格式报告 |

### 6.4 answer.csv 格式

```
qid,answer,prompt_tokens,completion_tokens,total_tokens
fc_a_001,A,1523,289,1812
fc_a_002,BC,2104,412,2516
```

- 单选题 / 判断题：单个大写字母（A-F）
- 多选题：多个大写字母按字母序拼接（如 `AC`、`BDE`）
- 空答案兜底为 `A`（避免被判非法）

## 7. Qwen LLM 配置

### 7.1 API 调用参数

当前 Qwen API 调用配置（`api/services/qwen_client.py`）：

| 参数 | 值 | 说明 |
|------|----|------|
| `temperature` | 0 | 确定性输出 |
| `enable_thinking` | True | 开启深度思考 |
| `thinking_budget` | 2560 | 思考 Token 预算 |
| `max_tokens` | 3072（单选/判断）/ 4096（多选） | 最大输出长度 |
| `response_format` | json_object | 强制 JSON 输出 |
| `timeout` | 90s | 请求超时 |

### 7.2 分题型 Prompt 架构

根据题目 `answer_format` 标签，系统自动选择不同的 Prompt 构建策略：

| answer_format | 映射 | Prompt 策略 |
|---------------|------|-------------|
| `single` / `mcq` | single | 排除法 + 选最强证据 |
| `multi` | multi | 逐选项独立判断，无法确认的不选 |
| `tf` / `judge` | judge | 否定表述检测 + 例外条款检测 |

> **设计要点**：Prompt 中不包含 reasoning_hints（规则推理器输出），避免关键词匹配产生的误判信号误导 LLM。

### 7.3 三级重试机制

`answer_with_qwen` 内置 3 次重试：

1. **首次调用**：分题型完整 Prompt（10 chunks × 600 字证据）
2. **二次重试**：简化 Prompt（5 chunks × 300 字，无 hints）
3. **三次重试**：简化 Prompt 再试（Qwen 非确定性，重试可能成功）

### 7.4 证据溯源自检

触发条件（`api/services/formatter.py` 的 `needs_self_check`）：
- 所有多选题（多选易漏选/多选）
- 单选/判断题无 support 信号时（低置信度）

自检流程（`api/services/qwen_client.py` 的 `verify_with_qwen`）：
1. 对第一轮**选中的**选项：要求引用证据原文证明，找不到直接证据则剔除
2. 对第一轮**未选的**选项：检查是否有支持证据，找到则纳入
3. 证据明确排除的选项不选

自检独立于 reasoning_hints，使用独立的 system prompt，确保验证的独立性。

## 8. 系统架构总览

```
题目输入
  │
  ▼
┌─────────────────────────────┐
│  Planner（问题分析）         │  → 领域检测、题型检测、关键词提取
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│  Retrieval Loop（CRAG 式）   │  → 最多 3 轮检索
│  ├ BM25 检索                 │
│  ├ 质量评估（8 维度评分）     │  → high(≥0.72) / medium(≥0.5) / low
│  └ 查询重写 → 重试            │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│  Formatter（规则推理 + 兜底）│  → 选项 verdict + fallback answer
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│  Qwen LLM（分题型 Prompt）   │  → 3 级重试
│  enable_thinking=True        │
│  thinking_budget=2560        │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│  Self-Check（证据溯源自检）  │  → 多选题 / 低置信度触发
│  独立 Prompt，逐选项验证     │
└──────────────┬──────────────┘
               │
               ▼
         最终答案 → answer.csv
```

## 12. 常见问题排查

### Qwen API 调用失败

1. 检查 `.env` 中 `DASHSCOPE_API_KEY` 和 `MODEL_NAME` 是否正确
2. 访问 `/api/health` 确认 `qwenEnabled: true`
3. 检查网络连通性（DashScope API 需要外网访问）
4. 查看 `results__<suffix>.jsonl` 中的 `llm_error` 字段

### Token 超限

- 当前单题 Token 预算：prompt ~2000 + completion ~2000 + thinking ~2560 ≈ 6500
- 全量 100 题预估 Token：~650,000（远低于 500 万预算）
- 如需降低 Token 消耗，可减少 `_format_evidence` 的 chunks 数量（当前 10 → 5）

### 预处理失败

1. 检查 PDF 文件是否损坏
2. 确认 PyMuPDF / pdfplumber / paddleocr 安装正确
3. 查看脚本输出中的错误日志
4. 使用 `scripts/resume_preprocess_public_dataset_a.py` 断点续跑

### 答案全选（多选题）

- 自检策略可能导致多选题过度纳入选项
- 检查 `results__<suffix>.jsonl` 中 `self_checked: true` 的题目
- 如需收紧自检，修改 `verify_with_qwen` 中的 prompt 措辞
