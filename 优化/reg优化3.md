这种提示词是否需要针对不同领域进行微调，因为不同领域可能要求也不太一样

### **不需要为每个领域调一套 prompt,但需要做一件事:在通用的七维清单上,用一个"严格度参数"区分领域的决策倾向。检查什么维度是通用的,但"存疑时倾向排除还是倾向纳入"是领域相关的。**

上一轮我给的七维框架里其实已经埋了两个层次:一是"检查清单"(七个维度,所有领域全跑),二是"域重点提示"(告诉 Qwen 哪个维度多留心)。后者是轻量的,但真正决定 research 和 regulatory 不打架的,是前者之外被忽略的第三个层次——**决策严格度**。下面把这三层拆开讲。

---

### **一、三层中只有一层需要按领域区分**

| 层次 | 是否通用 | 是否需领域微调 |
|---|---|---|
| 检查清单(七维) | 完全通用,所有领域全跑 | 不需要 |
| 域重点提示(轻量) | 通用框架内的强调词 | 需要,但只是引导,不改逻辑 |
| **决策严格度(存疑时的倾向)** | **领域相关** | **需要,这是关键** |

这三层里,只有第三层是真正需要按领域设参数的,而且只需要一个参数,不是三套 prompt。

**检查清单为什么通用**:七维(实体、数值、方向、逻辑结构、修饰语、来源角色、范围)覆盖了你观察到的所有错误模式,不管哪个领域,错题的根因都落在这七个里的一两个。research 的"增长/微降"是方向维,regulatory 的"才/或"是逻辑结构维,它们天然落在不同维度上,不需要为某个领域专门加或减一个维度。

**域重点提示为什么只是轻量引导**:它不改变逻辑,只是告诉 Qwen "这个行业里维度3和维度1容易出问题,多留心"。这是优化注意力分配,不是改规则。即使不加这个提示,七维照样全跑,只是 Qwen 可能不会优先看那个维度。

**决策严格度为什么是关键**:这才是 research 和 regulatory 失败模式相反的根源。research 错在"多选假选项",所以存疑时应该**倾向排除**;regulatory 错在"漏选真选项",所以存疑时应该**倾向纳入**。这不是检查维度的问题,是"门槛放多高"的问题。

---

### **二、为什么不用为每个领域写一套 prompt**

如果按领域写三套 prompt,会立刻回到打补丁的老路:research 的 prompt 偏保守,regulatory 的偏包容,你每加一个新错误类型就得想"它属于哪套、改哪个 prompt、会不会影响另一套"。七维框架的价值恰恰在于:**检查逻辑统一,只有决策参数变。**

打个比方,七维是质检员检查的七个项目(外观、尺寸、材料、焊接、密封、电气、包装),不管生产的是手机还是汽车,这七个项目都要查。但"容差率"可以不同:手机精密件要求零缺陷,汽车焊接可以接受万分之三的瑕疵率。你不会为手机和汽车写两套质检手册,只会调一个"容差"参数。

### **三、决策严格度怎么设**

只引入一个领域参数 `strictness`,它控制的是 Qwen 在"七维检查结果模糊"时的默认动作:

```text
strictness = "high"   (research/财报/研报)
  → 任何维度的疑似冲突,倾向不选
  → 证据不足时,默认排除
  → 多选题:宁可漏选,不可错选

strictness = "balanced" (保险/合同)
  → 明确冲突才排除,模糊的不排除
  → 证据不足时,标记待定

strictness = "inclusive" (监管法规)
  → 只有明确冲突才排除
  → 证据已支持且文档在范围内,即使主题略偏也纳入
  → 多选题:宁可错漏(保守),但已证的不要丢
```

这个参数不需要写进一套新 prompt,而是在七维 prompt 的"最终答案规则"那一段用变量注入:

```text
## 最终答案规则（当前领域: {domain}, 严格度: {strictness}）

{strictness == "high"}:
  多选题:只选七维全部通过且无任何疑似冲突的选项。
  存疑即排除。宁可漏选,不可错选。

{strictness == "inclusive"}:
  多选题:只要七维无明确冲突且证据直接支持,即纳入。
  不得以"主题偏移/范畴不符"为由排除已证选项。
  只有当某维度存在明确反证时才排除。
```

这样 research 域跑 `high`,Qwen 看到模糊证据倾向不选(抑制 001/017/019/020 的过度选择);regulatory 域跑 `inclusive`,Qwen 看到已证选项倾向保留(抑制 011-D/020-D 的过度剔除)。**同一个 prompt,一个变量,两域不打架。**

### **四、那"域重点提示"要不要保留**

可以保留,但定位要清楚:它是**锦上添花的注意力引导**,不是逻辑分支。它的作用是让 Qwen 在七维都查的情况下,优先深入查某个维度。即使它没写,Qwen 仍然会查全七维,只是可能对那个领域的典型陷阱不够警觉。

```text
## 当前领域提示
{domain == "research"}:
  本领域常见陷阱:实体混淆(维度1)、数值符号相反(维度2)、
  方向词矛盾(维度3)、核心数值未出现(维度2)。

{domain == "regulatory"}:
  本领域常见陷阱:逻辑连接词矛盾(维度4)、申辩冒充认定(维度6)、
  以主题偏移排除已证选项(维度7)、文末施行日漏读(维度2)。
```

注意:提示写的是"常见陷阱",不是"只查这个"。它不改变"七维全查"的硬性要求,只是提醒 Qwen 在这个领域,这几个维度历史出过错,仔细看。

### **五、完整的 prompt 拼装结构**

最终 prompt 是"通用骨架 + 两个注入变量",不是三套 prompt:

```text
[通用七维检查清单]           ← 所有领域完全一致
[域重点提示]                  ← 轻量引导,1-2行,变量注入
[最终答案规则(strictness)]   ← 决策严格度,变量注入
[题目+选项+证据]              ← 题目数据
```

拼装函数:

```python
def build_prompt(domain, answer_format, question, options, evidence):
    strictness = DOMAIN_STRICTNESS.get(domain, "balanced")
    domain_hint = DOMAIN_HINTS.get(domain, "")
    return HEADER + SEVEN_DIMENSIONS + domain_hint + \
           format_decision_rule(strictness, answer_format) + \
           format_question(question, options, evidence)
```

整份 prompt 里真正按领域变的只有两行变量注入,其余完全统一。这比写三套 prompt 好维护得多,也不会出现"改了 research 的 prompt 忘了同步 regulatory"的问题。

### **六、这套设计为什么不退化回打补丁**

你可能担心:给 regulatory 加"申辩冒充认定"的提示,不又是在打补丁吗?区别在于:

- **打补丁**:加一条具体规则("当事人提出"→ 不选),它是硬逻辑分支,改了会直接影响所有题。
- **框架提示**:它是"提醒 Qwen 多看维度6",Qwen 仍然要自己判断这个维度的检查结果。即使提示没写,Qwen 也会查维度6;写了只是让它更警觉。

换句话说,提示是**软引导**,补丁是**硬规则**。软引导写错了或漏了,最多是这个领域某个维度查得不仔细,不会系统性改变逻辑;硬规则写错了,直接把对题打成错题。框架的安全性来自于"逻辑是统一的,变量只调倾向"。

### **七、B 榜遇到新领域怎么办**

B 榜可能遇到题目问法和文档类型你 A 榜没见过的。这套设计的好处在这里显现:你不需要为新领域写 prompt,只需要给它分配一个严格度。

- 像研报/财报这种"数字密集、表述松散、容易过度选择"的 → `high`
- 像法规/合同这种"逻辑严密、条款引用多、容易过度剔除"的 → `inclusive`
- 拿不准的 → `balanced`

七维清单原封不动跑,新错误类型大概率落在七个维度之一,Qwen 用通用逻辑就能捕获,不需要你预先枚举。

### **总结**

七维检查清单本身不需要按领域微调,它是通用的。需要按领域区分的只有一个东西:**多选题在"证据模糊"时的决策严格度。** 把它做成一个 `strictness` 变量注入到通用 prompt 的"最终答案规则"段,比写三套 prompt 干净得多,也比硬规则补丁安全得多——因为它改的是倾向,不是逻辑。research 跑 `high`、regulatory 跑 `inclusive`,同一个框架,两个变量值,你之前那两个域"打架"的问题就消解了。
